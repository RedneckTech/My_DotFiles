# 3270BBS dev environment (the user's 3270 host)

Minimum to log in and drive the user's moshix/3270BBS dev environment
directly from Hermes, without re-deriving it. Deep reference lives in the
OpenCode agent docs (`~/.user_config/home/.config/opencode/agents/3270DEV.md`
and `ispf-editor.md`) and the manual on the host
(`~/3270BBS/3270UserGuide.pdf`, Chapter 16 = the full-screen editor). When
those cover a topic, this file only points to them.

## Host facts

- TN3270 plaintext at `192.168.122.151:3270` — the VM is on DHCP, so the IP
  drifts; find the current one with `virsh net-dhcp-leases default` (see
  SKILL.md Pitfalls). Launch: `x3270 -script -model 3279-2 <ip>:3270`.
- Login `admin` / `admin`. FIRST login shows a "User Profile" screen — press
  `PF(3)` to skip it.
- Maintenance via SSH alias `3270BBS` (user `dev`), install dir `~/3270BBS`,
  binary `tsu`. Start:
  `ssh 3270BBS 'cd ~/3270BBS && nohup ./tsu > tsu.log 2>&1 &'`.
- Programs are stored as PLAIN FLAT FILES in the install dir, NOT in the
  database: BASIC source at `basic/<user>/*.bas`, CHECK listings at `*.list`,
  program data/indexed files at `*.idx`/`*.dat`, assembler at
  `assembler/<user>/*.asm` (+ `*.list`). `tsu.db` holds only BBS social data
  (posts, mail, chat, notes, users) — never program source. So pulling a
  program back off the host is a plain `ssh`+`tar` of those extensions (or
  `scp`), not a screen-scrape; FTPD is disabled (`start_ftpd=no`). The
  project's `bbs-server/fetch.py` does this: streams
  `*.bas *.asm *.list *.idx *.dat` into `<repo>/bbs/` — project-agnostic,
  run it from any repo (defaults to the cwd's git root), and it is
  FETCH-ONLY by default: commit by handing the tree to the `git` subagent
  (approved-verb subjects, one commit per program) or pass `--commit`.
- `bbs-server/uploader.py FILE.bas` types a local `.bas` into the ISPF
  editor and saves it. `--verify` works: after PF(12) it polls for the
  `SAVED` confirmation (or `READY`) before running `load`/`check`, because
  the F12-save transition paints blank for up to 60s and a single `Wait()`
  returns on the blank. The post-save screen shows `SAVED name.bas` + `>`,
  NOT the `READY` banner — poll for `SAVED` OR `READY`, never `READY` alone.
  If the editor is left open with unsaved changes, `PF(3)` then `PF(9)`
  abandons and returns to READY.

## BASIC language gotchas (v3.0.0)

Full verified language reference lives in the repo at
`basic-learning/LANGUAGE_REFERENCE.md` (more accurate than the bundled
v2.9.2 manual); the whole set is MIRRORED at
`~/.user_config/ai/references/timesharing-basic/` in the dotfiles repo, so
it is available on every machine even where the 3270BBS project is not
checked out (`basic-learning/` stays the project working copy);
`basic-learning/DEF_FN_REFERENCE.md` has the DEF FN deep
reference plus a catalog of usage patterns (math helpers, predicates,
lookup tables, composition, control flow, formatting, INPUT validation);
`basic-learning/BOXCHAR_CP310_REFERENCE.md` has the full box-drawing /
graphics character tables; `basic-learning/UI_PANELS.md` is the cookbook
for building panels/menus/tables/progress bars with them;
`basic-learning/CHAIN_REFERENCE.md` covers program chaining
(`COMMON`/`CHAIN`); `basic-learning/ISAM_REFERENCE.md` covers indexed
files; `basic-learning/FILE_IO_REFERENCE.md` covers sequential file I/O;
`basic-learning/TIME_REFERENCE.md` covers date/time;
`basic-learning/STRING_REFERENCE.md` covers string functions;
`basic-learning/MATH_REFERENCE.md` covers math and operators; and
`basic-learning/MANUAL_ERRATA_FOR_DEV.md` is the consolidated list of every
place the bundled manual disagrees with the live interpreter (plus the
interpreter bugs found in testing).
Key gotchas:

- Label-based programs LOAD fine from a `.bas` file (reports `(LABEL MODE)`)
  but CANNOT be typed interactively at the `>` prompt: a bare `START:` line
  is `?SYNTAX ERROR` because `:` parses as a statement separator, not a
  label marker. Enter label programs via the ISPF editor or write the `.bas`
  file and `LOAD` it. Line-numbered programs type interactively fine.
- The bundled `basic_manual.md` documents v2.9.2; the server runs v3.0.0.
  `CHECK` in v3.0.0 only emits the loop-without-SLEEP warning — the manual's
  "insufficient comments" and "complex lines" warnings are not active.
- Arrays are 0-indexed (`DIM A(3)` gives `A(0)..A(3)`). `RND(1)` returns 1
  (deterministic); use `RND(0)` for a random float, `RND(n)` for a random
  integer in range. The manual's `DEF FNR(N) = INT(RND(1) * N + 1)` example
  is therefore broken — it always returns `N+1`, not a random value; use
  `RND(0)` in place of `RND(1)`.
- Filenames are capped at 10 characters (`?FILE NAME TOO LONG (MAX 10
  CHARACTERS)`). Keep `.bas` names to 10 chars or fewer or the editor save
  fails. (The manual's 8-character label limit is NOT enforced in v3.0.0 —
  a 24-char label loads and runs fine.)
- `+` is string concatenation when EITHER operand is a string: `"5" + 3` =
  `"53"` (not `8`), `A$ + 1` = `"hello1"`. No type error — this is the #1
  footgun. `INT()` floors, not truncates (`INT(-3.7)` = `-4`). Division by
  zero (and `x MOD 0`) raises `?DIVISION BY ZERO` and terminates the
  program — NOT a silent stop.
- Comparisons return **-1 for true, 0 for false** (not 1). `AND`/`OR`/`NOT`
  work in expressions. This matters for predicate functions and any
  arithmetic on a comparison result: `X = (A = B) * 10` gives `-10`, not
  `10`. `IF` still treats any non-zero as true, so `-1` works in conditions.
- `BOXCHAR$(n)` (n=1-6) and `CP310$(n)` (n=1-50) return box/graphics chars.
  Out-of-range is a RUNTIME error (`?BOXCHAR$ INDEX MUST BE 1-6` /
  `?CP310$ INDEX 0 NOT DEFINED (USE 1-50)`), not a silent return; non-integer
  args are floored. The x3270 emulator does NOT render the double-line box
  set (`CP310$` 7-12) — they show as `■` even though the bytes are correct —
  so use `BOXCHAR$` (single-line) for portable boxes and reserve `CP310$`
  7-12 for terminals that support them.
- Building panels: there is NO vertical cursor positioning (no `LOCATE`/
  `GOTOXY`) — output flows top-to-bottom; position horizontally with
  `TAB(n)`/`SPACE$(n)`. A border built by concatenating many `BOXCHAR$(5)`
  calls inline exceeds the 255-char line limit and the whole line is
  SKIPPED at load (`?WARNING: LINE TOO LONG`) — build horizontal lines with
  a loop. See `basic-learning/UI_PANELS.md`.

### DEF FN (user-defined functions)

- `DEF FNname(param) = expression` — exactly ONE parameter (zero params →
  `?EXPECTED PARAMETER NAME`, two → `?EXPECTED ) AFTER PARAMETER`). Name is
  `FN` + one letter/digit/underscore (`FN1`, `FN_`, `FNSQ` all work; bare
  `FN` fails). No length limit.
- DEF FN is a RUNTIME declaration: the function is usable only AFTER the
  DEF FN statement has executed. A `GOTO` that jumps over the DEF FN leaves
  it undefined (`?UNDEFINED FUNCTION`). Put DEF FN at the top, before any
  use.
- The parameter shadows a global of the same name, and the function reads
  globals at CALL time (not definition time). `DEF FND(X) = SQR(X^2 + Y^2)`
  with `X=3: Y=4` gives `FND(0)` = `4`, not the manual's claimed `5`.
- No recursion: a function calling itself → `?RECURSION TOO DEEP`. A
  function CAN call other functions (nested calls work).
- Return type is set by the EXPRESSION, not the `$` suffix: `DEF FNA(X) =
  X + "abc"` returns a string, `DEF FNA$(X$) = VAL(X$)*2` returns a number.
  The parameter type IS set by the `$` on the parameter name: a numeric
  param rejects a string arg (`?TYPE MISMATCH`), a string param coerces a
  number arg.
- Functions persist across CHAIN but are cleared by NEW. Redefinition is
  allowed (last wins). Variable names starting with `FN` are reserved and
  evaluate to blank in expressions — never use `FN...` as a variable name.

### Indexed files (ISAM)

`OPEN "f.dat" FOR INDEXED AS #n KEY = "field"` + `PUT`/`GET`/`DELETE`/
`RESET`/`FOUND(n)`/`DELETED(n)`/`EOF(n)`. Records are associative arrays
(`DIM C{}`). Verified behavior:

- Record numbers are **1-based**: `GET #1, R{}, REC = 1` returns the first
  record; `REC = 0` → `FOUND(1)` = 0 (not found).
- Sequential access (`RESET #1` then `GET #1, R{}, NEXT`) returns records in
  **INSERTION order, NOT key order** — the "index" is a key→record map for
  random access, not a sort. Do not assume a key-sorted scan.
- Keys can be numeric or string (`KEY = 200` and `KEY = "002"` both work).
- `PUT` **upserts**: writing a record whose key already exists updates it in
  place rather than adding a duplicate.
- **`PUT` and `GET` do NOT clear the record array** — fields from the
  previous operation leak into the next record. A record written with only
  `{id, city}` right after one written with `{id, name, age}` ends up
  carrying `name` and `age` too; a `GET` into an array still holding an
  earlier record's fields returns those stale values for absent fields.
  Re-`DIM arr{}` before EACH PUT and EACH GET — `DIM arr{}` clears an
  associative array. This is the #1 ISAM trap.
- Records are schemaless: different records may have different fields, and a
  field a record lacks reads back as `0` (numeric default), not `""`.
- `DELETE` is a SOFT delete: the record's line is prefixed with a `0x7F`
  byte rather than removed. `GET ... NEXT` skips deleted records, and
  re-adding a deleted key appends a NEW record (it does not reuse the slot).
  `DELETED(n)` reported wrong values in testing — do not trust it.
- The `.dat` is plain text: newline-separated records, TAB-separated
  `name=value` fields; no separate `.idx` file is created and the index is
  rebuilt on OPEN (so CLOSE then re-OPEN works). The general file-handle
  limit is 8 (`#1`-`#8`, see file I/O below), not the manual's 4. Errors: `?KEY FIELD 'id' NOT SET` (PUT without the key) and
  `?FILE NOT OPENED FOR INDEXED` (PUT/GET on a non-indexed file).
- Full reference: `basic-learning/ISAM_REFERENCE.md`.

### Program chaining (COMMON/CHAIN)

- Variables do NOT cross a `CHAIN` unless declared `COMMON` in the CALLER:
  without it the chained program sees `0`/`""` and its writes are lost. Only
  the caller must declare `COMMON` — the callee inherits the shared vars.
  Open files and `DEF FN` functions also persist across `CHAIN`; a missing
  target is `?PROGRAM NOT FOUND`. Full detail:
  `basic-learning/CHAIN_REFERENCE.md`.

### Sequential file I/O

- File handles are `#1`-`#8`, NOT `#1`-`#4` — both the manual AND the error
text (`?BAD FILE NUMBER (MUST BE 1-4)`) are wrong; 8 files can be open at
once. The handle must be a LITERAL: `AS #H` → `?EXPECTED FILE NUMBER AFTER
#`.
- Filenames must end `.dat`; `.idx`/`.txt` → `?ILLEGAL FILE NAME`. The
manual claims `.idx` is allowed — it is NOT, for sequential files.
- `INPUT #n, var` reads ONE LINE per variable: `INPUT #1, A, B, C` reads
three lines, not three comma-separated values from one line (a single
comma-separated line → `?INPUT PAST END`). Numeric parse stops at the first
non-numeric char; a non-numeric line reads as `0`.
- `INPUT #` cannot target an array element — `INPUT #1, N(2)` stores into
the SCALAR `N` (verified: `N(2)=0` but `N=42`). Read into a scalar, then
assign to the array.
- Writes are BUFFERED and land at `CLOSE` or normal program end; a runtime
error loses the buffer (a file written then errored before `CLOSE` was not
created at all). There is no `ON ERROR` handler. Full detail:
`basic-learning/FILE_IO_REFERENCE.md`.

### Time & date functions

`DATE$() TIME$() YEAR() MONTH() DAY() HOUR() MINUTE() SECOND() TIMER()
SLEEP(n)`. Full detail: `basic-learning/TIME_REFERENCE.md`. Key gotchas:

- `DATE$()` = `YYYY-MM-DD` and `TIME$()` = `HH:MM:SS`, both **zero-padded
  strings**; the component functions return **plain numbers** (`HOUR()` = 5,
  not `"05"`). `TIMER()` = seconds since midnight (float, sub-second).
- `SLEEP(n)` range is **0.1-255 seconds**; 0, negative, <0.1, or >255 →
  `?SLEEP VALUE OUT OF RANGE (0.1-255)`. Returns 0, non-busy.
- **`SLEEP` grants execution-time credit**: over-running raises
  `?EXECUTION TIME LIMIT REACHED` (15s limit), but frequent `SLEEP` calls
  extend it by roughly 15% (a ~16s-CPU loop completes with `SLEEP` every
  250k iterations; a ~21s one still fails).
- There is **no `DAYOFWEEK()`/`DAYOFYEAR()`** — and undefined function calls
  do NOT error, they evaluate to empty (so a typo'd function silently yields
  nothing). Compute day-of-week/year yourself.
- `STR$` prepends a space to NON-NEGATIVE numbers **at runtime**, but the
  optimizer precomputes a LITERAL argument WITHOUT the space — `STR$(5)` =
  `"5"` yet `STR$(H)` (H=5) = `" 5"`. The SAME expression differs by literal
  vs variable (a real trap). Zero-pad with
  `RIGHT$("0" + TRIM$(STR$(n)), 2)`, never `RIGHT$("0" + STR$(n), 2)`.
- Because `TIME$()` is zero-padded, plain string comparison of times is
  correct (`"05:00:00" < "06:00:00"`). Time is the host's local time.

### String functions

Full detail: `basic-learning/STRING_REFERENCE.md`. Gotchas:

- **Strings cap at 2048 bytes** — over that → `?STRING TOO LONG (MAX 2048
  BYTES)` (the manual's "no fixed maximum length" is wrong). `SPACE$` caps
  lower, at 255 (`SPACE$(0)` → `""`).
- String comparison is **case-sensitive, ASCII order**: `"abc" = "ABC"` is
  false and `"a" < "A"` is false (uppercase sorts first).
- `MID$(s$, 0, n)` → `?ILLEGAL QUANTITY ERROR` (position must be ≥ 1);
  `LEFT$`/`RIGHT$` with n=0 give `""`, n>len clamps; `MID$` with no length
  runs to the end.
- **`STRING$(n, char)` does NOT exist** — the manual mentions it, but it is
  parsed as an array (`?ARRAY NOT DIMENSIONED: STRING$`).
- No `s$(n)` subscript; extract one char with `MID$(s$, n, 1)`. `CHR$`
  embeds control chars: `CHR$(9)` tab, `CHR$(10)` newline.

### Math functions

`ABS INT SGN SQRT SQR SIN COS TAN ATAN ASIN ACOS LOG EXP RND PI RADIANS
DEGREES`. Full detail: `basic-learning/MATH_REFERENCE.md`. Gotchas:

- **`RND`'s argument is a RANGE, not a seed**: `RND(0)` = random float in
  `[0,1)`; `RND(n)` for n≥1 = random INTEGER in `[1,n]` inclusive; `RND(1)`
  = `1` always. So a random integer in `[1,N]` is just `RND(N)` — the
  manual's `INT(RND(1)*N+1)` is wrong (it always returns N+1). `RND(0.5)`
  → `?ILLEGAL QUANTITY ERROR`.
- **No `ROUND`/`CEIL`/`FLOOR`/`MIN`/`MAX`** — they parse as arrays
  (`?ARRAY NOT DIMENSIONED: ROUND`). Use `INT`: `FLOOR = INT(x)`,
  `CEIL = -INT(-x)`, `ROUND = INT(x + 0.5)`.
- Precedence, highest first: `^` (RIGHT-associative — `2^3^2` = 512) > unary
  `-` (`-2^2` = -4) > `*` `/` `MOD` > `+` `-`. `/` is floating-point
  (`10/3` = 3.333...); `MOD` sign follows the dividend (`-7 MOD 3` = -1).
- Domain errors → `?ILLEGAL QUANTITY ERROR`: `SQRT(-1)`, `LOG(0)`, `LOG(-1)`,
  `ASIN(2)`/`ACOS(2)`, and a negative base with a fractional exponent
  (`(-8)^(1/3)`). `0^0` = 1 (defined); `2^-1` = 0.5.
- Numbers are IEEE-754 doubles: `0.1+0.2` = `0.30000000000000004` (so
  `0.1+0.2 = 0.3` is FALSE); `2^53+1` = `2^53`. Display switches to
  scientific at ≥ 1e19 (`1e+19`) and < 1e-4 (`1e-05`).

## Testing BASIC programs (fast loop)

To exercise a program without typing it line-by-line, write the `.bas`
straight to the host and `LOAD`+`RUN` it through the fifo:

```
ssh 3270BBS 'cat > ~/3270BBS/basic/admin/NAME.bas << "EOF"
...program...
EOF'
# then via the fifo: String("LOAD \"NAME.bas\"") Enter, String("RUN") Enter
```

`LOAD` reads the file from disk directly (no directory-cache refresh
needed), so this is far faster than the ISPF editor for throwaway probes.
If the heredoc mangles the program (shell-special text can break it), write
the `.bas` to a local file and pipe it instead — more robust for programs
full of `$()`, quotes, and colons:
`ssh 3270BBS 'cat > ~/3270BBS/basic/admin/NAME.bas' < NAME.bas`.
`basic-learning/drive.py` wraps the fifo send/read (the 3270BBS helper
scripts — `drive.py`, `uploader.py`, `fetch.py` — are also mirrored at
`~/.user_config/ai/scripts/`):
`python3 drive.py 'String("LOAD \"NAME.bas\"")' Enter 'String("RUN")' Enter`
sends the batch and prints the resulting screen (`--wait N` to settle
longer, `--raw` to just dump the current screen). Inside `String()` escape
`\"` as `\\\"`; when passing actions as shell args use single quotes with a
SINGLE backslash, not `\\\"`.

A blind-settle driver (`sleep N` after the batch) can return BEFORE the host
has processed `LOAD`+`RUN` and print the PREVIOUS program's screen. If the
screen is unchanged from the last run, RE-SEND the batch rather than
concluding the program failed; confirm progress by the screen actually
changing (a new `RUNNING...` / the expected output), never by the fact that
the batch was written to the fifo.

To capture output without losing it to the 24-row screen scroll, have the
program `PRINT #1, ...` to a `.dat` file and read it back over SSH
(`ssh 3270BBS 'cat ~/3270BBS/basic/admin/NAME.dat'`). The 3270 screen shows
only 24 rows and an `Ascii` dump returns only the CURRENT screen, so a
program printing more than a screenful scrolls and the earlier lines are
lost. `CLEAR` before `RUN` frees the screen for short output; for anything
longer, redirect to a file.

`PRINT #n` uses the SAME comma(tab)/semicolon(concat) rules as screen
`PRINT` — there is NO special padding. The apparent "padding" in a data
file is the COMMA: it tabs to the next 14-column print zone (value 1 in
cols 1-14, value 2 at col 15, ...). Use `;` to concatenate with no
separator; a single expression writes unpadded. When writing a box/panel
row to a file, join it into ONE string with `+`, never with `,`.

## Navigation (BBS 4.2.5)

- Menu letters are case-insensitive. Main menu: `m` = Extended Menu, `s` =
  SDSF, `x` = TSO/Logoff, `n` = Notes, `3` = Search Content.
- BASIC and assembler are NOT on the main menu in 4.2.5. Go `m` (Extended
  Menu) then `b` (BASIC) or `a` (Assembler). The shortcuts `M;B` / `M;A` also
  work from the main menu.
- Confirm BASIC READY with `Ascii` + grep `READY`. The `M;B` -> READY and
  editor F12-save transitions paint BLANK for up to 60s — poll, don't queue.

## ISPF editor coordinates (1-origin)

- `edit "name"` from READY. The cursor lands in the `Command ===>` field
  (row 2, col 15+) — type primary commands immediately; don't MoveCursor1
  into row 2.
- Row 2 right end: `Scroll ===>` value at cols 70-72 (`CSR`/`PAGE`/`HALF`).
  Change how far F7/F8 scroll: `MoveCursor1(2,70)` + overtype + `Enter`.
- Data lines: prefix area at col 3 (line commands), text at col 9 (overtype
  edit in place).
- Line commands (type over the `''''''` prefix, one `Enter`): `D` delete,
  `I` insert, `R` repeat, `C`/`M` copy/move (mark source + destination `A`
  after / `B` before / `O` overlay before the same Enter; block = `CC`/`MM`
  on two lines), `U`/`L` case, `)`/`(` shift, `X` exclude. A trailing digit
  repeats (`D3`, `I5`).
- Bulk-appending a program: insert a BATCH of blanks at once (`I50`) rather
  than one `I` per line, then type into the pre-inserted blanks. Track the
  remaining-blank count so the next `I50` fires only after the batch is used
  up. One `I` per line is slow and, worse, the editor ignores `I` on the
  last data row (row 23) — scroll with `PF(8)` and re-locate the last typed
  line by its text (Ascii + search) before continuing below it.
- After `PF(8)` scrolls down past the top, the "Top of Data" border line
  becomes a 21st data row (data then occupies rows 3-23, not 4-23). Do NOT
  track the on-screen line by a fixed page-height formula across scrolls —
  that one-row shift accumulates and silently drops lines. Re-locate the
  last typed line by Ascii-dumping and matching its text, and derive the
  next row from that.
- `F1` = on-screen panel (abbreviated command list); full set in the manual.

## Recovery

- Blank screen = slow paint (M;B, F12 save, load/run, line commands) — poll
  `Ascii` up to 90s before calling it a wedge; never queue actions during
  the blank.
- Server-side wedge (interrupted save OR rapid-fired line commands) — a
  fresh one-shot connection paints the logon screen instantly while your
  session stays blank; restart `tsu` on the host to clear it.
