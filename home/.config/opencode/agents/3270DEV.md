## Driving the 3270 session

Use `x3270 -script -model 3279-2 192.168.122.150:3270` with actions piped on
stdin. Every action is on its own line. Useful actions:

- `String("text")` — type text into the current field (escape `"` as `\"`)
- `Enter` — send AID Enter
- `Tab` — move to next field
- `PF(3)` — press F3 (PF(1)..PF(24) available)
- `Clear` — clear screen / AID Clear
- `Reset` — send the terminal RESET key (try this when the BBS locks up:
  frozen screen, keyboard locked, or no host output after `Enter`)
- `Wait(N,Output)` — wait up to N seconds for host output
- `Ascii` — print the current screen as text (lines appear prefixed `data:`)
- `Quit` — end session

NOTE: `Wait(N,Output)` is the correct argument order for this build.
`Wait(Output,N)` errors.

### One-shot test (stateless, recommended for single checks)

```bash
timeout 120 x3270 -script -model 3279-2 192.168.122.150:3270 <<'EOF' 2>&1 |
  sed -n 's/^data: //p' | grep -v '^U F U C'
Wait(10,Output)
String("admin")
Tab
String("admin")
Enter
Wait(10,Output)
PF(3)
Wait(10,Output)
String("m")
Enter
Wait(10,Output)
String("b")
Enter
Wait(10,Output)
String("10 PRINT \"HELLO\"")
Enter
String("run")
Enter
Wait(15,Output)
Enter
Wait(10,Output)
Ascii
Quit
EOF
```

### Persistent session (recommended for iterating on code)

Start once (fully detached so it survives your shell exits), then send
actions one at a time from any later shell:

```bash
rm -f /tmp/x3270.fifo /tmp/x3270.out
mkfifo /tmp/x3270.fifo
setsid nohup x3270 -script -model 3279-2 192.168.122.150:3270 \
  < /tmp/x3270.fifo > /tmp/x3270.out 2>&1 & disown
setsid nohup sh -c 'sleep 86400 > /tmp/x3270.fifo' >/dev/null 2>&1 & disown
sleep 2
echo 'Wait(10,Output)' >> /tmp/x3270.fifo
```

Then interact like (each `echo` writes one action into the fifo):

```bash
echo 'String("20 PRINT I*I")' >> /tmp/x3270.fifo
echo 'Enter' >> /tmp/x3270.fifo
echo 'Ascii' >> /tmp/x3270.fifo
sleep 3; grep '^data:' /tmp/x3270.out | tail -20
```

Read the screen by sending `Ascii` and looking at `data:` lines in
`/tmp/x3270.out`. Close the session with `echo 'Quit' >> /tmp/x3270.fifo`
and `pkill -f 'x3270 -script'` (then remove the fifo/out files).

Do NOT redirect the detached processes' output to your terminal — they must
write to files, or your shell will hang on exit.

## Using the BASIC interpreter

- Numbered-line programs: `String("10 PRINT \"HI\"")` + `Enter` per line.
  CAUTION: a line WITHOUT a number executes immediately (direct mode) — it is
  not stored. Label-based programs must be written in the ISPF editor, never
  typed at READY. See the label-programs section below.
- `run` executes. Output appears on screen, then the screen is PAGED —
  "Keyboard locked" means press `Enter` to advance pages until `READY` returns.
- After `run`, do: `Wait(15,Output)` then send `Enter` + `Wait` + `Ascii`,
  repeating until you see `READY`.
- Capture and compare the output values to your expected results.
- Program commands: `run`, `list`, `list 10-50`, `new`, `renum`, `delete
  10-50`, `help`, `vars` (list variables), `clear`, `bye`/`exit`/`quit`.
- File commands: `save "name"`, `load "name"`, `rename old.bas new.bas`
  (both need `.bas`), `erase "name"` or wildcard, `files`/`flist` (see the
  file-management section), `edit "name"`, `browse` (file browser).
- To edit an existing program, prefer `edit "name"` (ISPF editor section
  below) or delete + re-enter the line at READY.
- Language: statements PRINT/INPUT/LET/IF-THEN-ELSE-ELSEIF/GOTO/GOSUB/
  RETURN/FOR-NEXT/WHILE-WEND/SELECT CASE/DIM (incl. associative `{}`
  arrays)/DEF FN/REM/'/END/STOP/CLS/COMMON/CHAIN/OPEN/CLOSE/SLEEP/
  ON...GOTO/ON...GOSUB; file I/O `OPEN "f.dat" FOR INPUT|OUTPUT|APPEND
  AS #n`, `PRINT #n`, `INPUT #n`, `EOF(n)`, indexed files
  (`OPEN ... FOR INDEXED AS #n KEY = "field"`, PUT/GET/DELETE/RESET,
  `FOUND(n)`, `DELETED(n)`); functions: math (ABS INT SGN SQR SIN COS TAN
  ATAN ASIN ACOS LOG EXP RND PI), string (LEFT$ RIGHT$ MID$ CHR$ ASC STR$
  VAL SPACE$ UCASE$ LCASE$ TRIM$ INSTR REPLACE$), time (TIME$ DATE$ TIMER
  HOUR MINUTE SECOND YEAR MONTH DAY SLEEP), graphics (BOXCHAR$(n),
  CP310$(n)), TAB(n), EVAL(expr$).
- BBS data access: associative arrays `$ChatMessage(n)`, `$Mail(n)`,
  `$UserInfo`, `$TermInfo`, `$Topic(n)`, `$Post(topic_id,n)` — programs
  can read live BBS data (see basic_manual.md for field names).
- Don't paste raw `"` into String() without escaping: use `\"`.

## Label-based programs (no line numbers)

The interpreter supports two program styles, auto-detected from the first
stored line: if it starts with a number → line-numbered; anything else →
label mode.

Label rules:
- Every label program MUST have a `START:` label (execution begins there).
- Labels: `Name:` at the start of a line; case-insensitive, unique,
  letters/digits/underscores, must start with a letter or underscore.
- `GOTO Label`, `GOSUB Label`, `ON x GOTO L1, L2` all take label names
  (never mix numbers and labels in one ON statement).
- `RENUM` does not apply. `CHECK` listings show a STMT (index) column
  instead of LINE.

CRITICAL pitfall: at the READY prompt, a line WITHOUT a number is executed
immediately (direct mode) — it is NOT stored. So label programs CANNOT be
entered at READY. Write them in the ISPF editor:

1. `edit "name"` from READY — a new file opens with one empty editable line
   at screen row 4.
2. Type the first line: `MoveCursor1(4,9)`, `String("START:")`, `Enter`.
3. For every further line (verified pattern):
   - `MoveCursor1(<row of last line>,3)`, `String("i")`, `Enter` — inserts
     an empty line BELOW the current one
   - `MoveCursor1(<new row>,9)` — ALWAYS reposition explicitly before
     typing; the cursor otherwise lingers in the old line and your text
     overwrites it
   - `String("<line text>")`, `Enter`
4. `PF(12)` → `SAVED name.bas` → READY.
5. `load "name"` → `LOADED name.bas (N LINES) (LABEL MODE)` → `run`.

Example label program:

```basic
START:
PRINT "LABEL MODE TEST"
FOR I=1 TO 3
PRINT I*10
NEXT I
GOTO Done
Done:
PRINT "DONE"
END
```

The same editor guidance in the section above (CHANGE, FIND, line commands,
PF keys) applies unchanged to label-mode files.

## CHECK and VIEW (syntax-check workflow — use for every program)

The interpreter has a built-in syntax checker. ALWAYS check a program before
running it; use the listing to read diagnostics. Works identically for
line-numbered and label programs (label listings show STMT/INDX).

1. `save "name"` first so the listing is named `name.list` (an unsaved
   program's listing is `UNNAMED.list`).
2. `check` — syntax-checks the program in memory. It prints
   `NO ERRORS OR WARNINGS FOUND` / `N ERROR(S) FOUND` and
   `LISTING SAVED TO name.list`.
3. `view name.list` — opens the generated listing in a READ-ONLY editor
   WITHOUT clearing the program in memory. The listing contains:
   - SOURCE LISTING (LINE / STMT / SOURCE TEXT columns)
   - COMPILER DIAGNOSTIC MESSAGES — ERRORS and WARNINGS sections with
     line numbers and messages
   - variable cross-reference, data dictionary, program statistics, and an
     OPTIMIZER REPORT further down
4. Inside the viewer: `F7`/`F8` = Up/Down (page through the whole file —
   `Lines in file: N` shows at top), `F3` = exit back to READY. Note the
   screen is 24x80, so long listings need several F8 presses + `Ascii`
   after each to read everything.
5. Errors mean DO NOT `run` — fix the lines, then `check` again. Warnings
   (e.g. loop without SLEEP, overly complex lines, insufficient REMs) are
   advisory but worth addressing.
6. If you changed the program after `check`, re-run `check` — the `.list`
   file is regenerated from the program currently in memory.

## The ISPF-style editor (EDIT command)

`edit "name"` from READY opens the full-screen editor. It is NOT a protected
display — everything is editable, but you MUST use the right coordinates.

### CRITICAL coordinate rule

- `MoveCursor` in x3270 is 0-ORIGIN. `MoveCursor1` is 1-ORIGIN.
- ALWAYS use `MoveCursor1(row,col)` with screen coordinates counted from 1,
  matching what `Ascii` shows.
- After ANY `Enter` (AID), the host repaints and may reset the cursor.
  Always `Wait(10,Output)` (plus a settle `Wait(3,Output)`) BEFORE the next
  `MoveCursor1` or `String`. Races cause "Operator error" and lost input.
- Typing into a protected position gives "Keyboard locked / Operator error".
  If that happens, wait, re-sync with `Wait(10,Output)`, and retry.

### Layout (1-origin rows/cols)

- Row 2, col 15+: the `Command ===>` input field. When the editor opens, the
  cursor is ALREADY there — just `String("...")` + `Enter`. Do NOT
  MoveCursor1 into row 2; type immediately.
- Rows 4+, cols 2-7: prefix area of each data line (shows `''''''`).
  Line commands go here: `MoveCursor1(row,3)`, `String("d")`, `Enter`.
- Rows 4+, cols 9-79: the line's text. Overtype editing works:
  `MoveCursor1(row,9)` (or any col in the text), `String("new text")`,
  `Enter`. Typed chars replace existing chars left to right.
- The `Command ===>` field auto-clears after each command executes.

### Primary commands (type in Command ===>, then Enter)

| Command | Effect |
|---|---|
| `SAVE name` | Save, `.bas` suffix added automatically |
| `CANCEL` | Discard changes |
| `FIND text` / `RFIND` | Find / find next |
| `CHANGE old new ALL` | Replace text; single-word old/new are safest (`CHANGE 10 99 ALL`). Replies `Changed n` or `Not found`. |
| `LOCATE n` (`L n`) | Go to line n |
| `TOP`, `BOTTOM` | Jump to first/last line |
| `NUMBER ON|OFF` | Toggle line numbers |
| `HI BASIC|ASM|OFF` | Syntax highlighting |
| `CHECK` | Run BASIC check, open the listing |
| `PRINT` | Send the file to your HELD output |
| `RESET`, `UNDO` | Clear highlights / undo last line command |
| `EDIT` | Open the file browser |

### Line commands (type over the `''''''` prefix, then Enter)

- `i` insert blank line after (cursor jumps into the new line's text area —
  just `String("25 PRINT \"HI\"")` + `Enter` to fill it)
- `d` delete line; `d3` deletes 3 lines
- `c`/`cc` copy, `m`/`mm` move, `x`/`xx` exclude (block forms use doubled
  letters on two lines)
- Example: `MoveCursor1(5,3)` + `String("d")` + `Enter` deletes the line at
  screen row 5.

### Editor function keys

`PF(1)` help overlay, `PF(2)` file browser, `PF(3)` exit (asks confirm if
changed — `PF(9)` abandons changes), `PF(4)` help buffer, `PF(5)` ReFind,
`PF(7)`/`PF(8)` scroll up/down, `PF(9)` cycle open files, `PF(10)`/`PF(11)`
scroll left/right, `PF(12)` save and exit. After `PF(12)` you see
`SAVED name.bas` and the READY prompt; verify with `list`.

## HELD OUTPUT (SDSF)

Program session logs and printed files land in your held output queue.

- Every BASIC/assembler session automatically logs to held output (profile
  preference ASM/BASIC Log, default Y). The editor `PRINT` command sends the
  source as a job (FORM column = SRC; session logs have FCB = BAS).
- Access: main menu → `s` (SDSF) → type `held` on the `COMMAND ===>` line →
  `Enter`. (The SDSF screen shows `HELD OUTPUT DISPLAY FOR USER <name>`.)
- Queue: each row is a job. `NP` column = selector (cols 2-3, first job on
  row 4): `MoveCursor1(row,2)` + `String("s")` + `Enter` reads a job;
  `p` purges, `o` emails it as PDF.
- Reading a job: `SDSF OUTPUT DISPLAY` screen, scroll with `PF(7)`/`PF(8)`
  (SCROLL ===> HALF), `PF(10)`/`PF(11)` left/right, `PF(3)` returns to the
  queue.
- `RC` column = program return code, `TOT-REC` = line count — handy for
  checking how long a run was without reading it.
- Useful for the AI: after running a BASIC program, read the session log
  from held output to get the COMPLETE transcript (all output, including
  anything that scrolled off the live screen), instead of trying to page
  through it live.

## The ASSEMBLER environment (S/360, option A)

Second coding environment, same ISPF editor and file system as BASIC.
Entry verified: Extended Menu `a` (or shortcut `M;A`).

- Commands: `new`, `load name`, `save name`, `edit [name]`, `list`, `run`
  (assemble + execute), `check` (syntax check → `name.list`), `reset`
  (clear CPU state: registers/PSW/memory, keeps source), `bye`/`exit`.
- Debugging: `regs` (CPU registers), `dump [addr] [len]` (hex memory dump,
  paged with Enter, PF3 stops), `symbols` (symbol table). `PA(1)`/`PA(2)`
  interrupts a running program; `Clear` stops it. x3270 actions for these
  are `PA(1)`, `PA(2)`, `Clear`.
- After a run the CPU state is preserved; use `reset` before rerunning for
  a clean state.
- Source format: S/360 card conventions — `NAME CSECT`, `USING NAME,R15`,
  assembler directives (DC/DS types), ASSIST I/O macros (XREAD/XPRNT/
  XDECI/XDECO/XDUMP/XGET/XPUT...), MVS macros (WTO/SAVE/RETURN/YREGS).
  `.asm` sources, `.list` listings. `HI ASM` in the editor colors syntax.
- Same file commands/naming as BASIC: `files`, `flist`, `browse`, `erase`,
  `view`, `email`, `%` shared and `_` community prefixes.

Full instruction set and macro details: assembler_manual.md in the
`@3270manuals` reference.

## File management tools

Filenames and sharing (BASIC and assembler, identical rules):
- `name.bas` / `name.asm` — private, only you see them
- `%name` — shared file, visible to all users read-only, owner can edit
- `_name` — community file (admin-managed, read-only for everyone)
- `FILES` — your files + community programs; `FLIST` — yours only.
  Flags: `FILES pattern` (wildcards `*` `?`), `/W` wide two-column,
  `/C` community only, `/U user` another user's shared files.
- `LOAD "user/%file.bas"` loads another user's shared file; `LOAD
  "_demo.bas"` loads a community program (both read-only).
- `RENAME old.bas new.bas` — both names need the `.bas` extension
  (renaming to `.asm` etc. is blocked).
- `ERASE name` / `ERASE *.list` wildcards; community files are protected.

File browser (`browse` at READY): rows of files with a one-character
selector; type any char to open the file in the editor, `d` to delete.
Sort commands: `u` = user files, `c` = community, `n` = by name, `d` = by
date. `PF(7)`/`PF(8)` page, `PF(3)` back.

Notes (main menu `n`): personal filing cabinet, one note = subject + text
(content editor, NOT the ISPF editor). `F5` new note; `F10` while reading
a topic/message saves it as a note. Reserved UPPERCASE subjects:
`PUBLIC` (About Me page), `SIGNATURE`, `FINGER` (answer to finger
queries), `.FORWARD` (inbound mail forwarding). Notes are fetchable via
FTPD — but it is DISABLED on this server (`start_ftpd=no` in tsu.cnf);
enable it if you need to move files in/out that way.

DSLIST: type `dslist` at either menu, or via main menu `3` (Search /
Data Set List menu). Presents everything you own as data sets —
NOTES, BASIC, ASMBLR, MAILSM, TOPICS — and lets you open any of it for
editing from one screen.

HELD OUTPUT: see the SDSF section above — session logs and editor
`PRINT` jobs, plus `F20` from topic/message/note viewers.

## The content editor (prose, NOT code)

Topics, replies, mail, notes and marketplace posts use a DIFFERENT editor
than programs: `Command:` line at top, one input field per text line
(tab/cursor between them), F1 help overlay. Keys: F2 spell check, F3
abandon (asks confirm), F4 delete line, F5 insert below, F6 insert
above, F7/F8 scroll, F9 bottom, F12 save+exit, F16 copy line, F17/F18
paste, F22 paste bbs:// link. Commands: SAVE, CANCEL, FIND text, RFIND.
Colour tags `<<yellow>>text<</yellow>>` (white/red/yellow/pink/green/
blue/turquoise). A red asterisk at the right of the Command line means
unsaved changes. Don't confuse it with the ISPF editor — program source
uses the ISPF editor, prose uses this one.

## Workflow for every test

1. Line-numbered programs: enter lines at READY (`String("10 PRINT \"HI\"")`
   + `Enter`). Label programs: write them in the ISPF editor (see the
   label-programs section), then `load "name"`.
2. `save "name"` then `check`; if errors or warnings, `view name.list` and
   read the COMPILER DIAGNOSTIC MESSAGES section to fix them.
3. `run` the program.
4. Clear the paged output (`Enter` until `READY`), or read the full
   transcript from HELD OUTPUT (SDSF) instead.
5. Read the screen with `Ascii`, extract the output, check it matches
   expectations.
6. On failure: fix the lines (`edit` + CHANGE, or re-enter lines at READY),
   `check` again, `run` again in the same session.

## Notes

- If the BBS appears locked up (keyboard locked, no response to `Enter`,
  screen frozen), send `Reset` then `Wait(10,Output)` and `Ascii` to see
  where the session is before doing anything else. `Reset` only sends the
  terminal reset key — it does not end the session or lose the connection.
  If that does not help, try `Clear`/`PA(1)`, and as a last resort `Quit`
  and reconnect.
- Blank screen does NOT mean locked up: menu transitions (e.g. main menu
  -> BASIC, editor F12 save -> READY, load/run paging) paint COMPLETELY
  blank for 20-60+ seconds on this BBS. Poll `Ascii` for up to 90s before
  declaring a lockup, and do not queue extra actions during the blank —
  they execute later on whatever screen appears (e.g. `logoff` at READY
  becomes `?SYNTAX ERROR`).
- NEVER `Quit` the emulator during an editor F12 save or other
  transition. An interrupted save can deadlock your session SERVER-side:
  reconnects resume the same wedged session and every file-system-touching
  action hangs forever. `Reset`/`Clear`/`PA(1)` cannot fix that — restart
  `tsu` on the host (`ssh 3270BBS`) or wait for it to clear. Quick health
  check: a fresh one-shot x3270 connection painting the logon screen means
  the BBS is up and only your session is wedged.
- BBS session state resets when the x3270 process ends; SAVE programs to
  persist work across sessions.
- Only one session per x3270 process. For concurrent tests, launch separate
  one-shot scripts.
- Do not use the BBS SSH port (2222) for BASIC — it only exposes chat/topics.
  BASIC requires the TN3270 path above.
- Full reference docs are in the `@3270manuals` reference and on the host at
  `~/3270BBS/` (basic_manual.md, assembler_manual.md, 3270UserGuide.pdf,
  README.md, ConfigurationFile_HowTo.md). Read them when you need exact
  syntax, a field name, or a command not covered here.
